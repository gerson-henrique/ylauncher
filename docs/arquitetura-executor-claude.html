Executor Claude

O terminal que roda Claude direto no celular. Você fala, o Claude pensa, e executa comandos de sistema pela identidade do Shizuku — com um freio de mão antes de qualquer coisa destrutiva.

O laço, em uma imagem

você digita→ ClaudeViewModel→ Anthropic /v1/messages
claude-opus-5 + tool→ tool_use?
├ end_turn →resposta na tela
└ comando shell → comando perigoso? ├ não →ShizukuShell.run()
└ sim → banner Permitir / Negar →run() ou is_error →tool_result → volta pro laço

Laço manual de tool-use, sem streaming na v1: HttpURLConnection + org.json na mão, igual ao WeatherRepository. Nada de OkHttp nem SDK pesado — o app continua leve.

As sete peças

data/claude/ClaudeSecretStore.kt

Cofre da chave crítico

Chave da API cifrada com AES-GCM via Android Keystore, só o texto cifrado vai pro DataStore. Nunca no repo, nunca em log. Sem dependência nova — Keystore na mão, no espírito do resto do app.

data/claude/AnthropicClient.kt

Cliente HTTP

POST pro /v1/messages, JSON montado à mão, claude-opus-5, tool_choice: auto. Devolve blocos de conteúdo (texto + tool_use). Roda em Dispatchers.IO.

data/claude/ShellTool.kt

A ferramenta

Uma tool só: run_shell(command). Backend = ShizukuShell.run(), que já existe. Descrição prescritiva pro Opus 5 (diz quando usar, não só o quê).

data/claude/DangerGate.kt

Freio de mão

Classifica o comando antes de rodar. Perigoso = rm, reboot, pm uninstall, am force-stop de infra, settings put, wipe. Perigoso → o laço trava e pede confirmação. Você é o gate — a IA não roda nada destrutivo sozinha.

ui/claude/ClaudeViewModel.kt

Orquestrador

Segura a lista de mensagens (StateFlow), roda o laço numa corrotina, gerencia o estado "aguardando confirmação" e a saúde do Shizuku.

ui/claude/ClaudeScreen.kt

A tela

Chat: lista de mensagens + campo + enviar. Banner de confirmação pro comando perigoso. Banner "Shizuku caiu" com conserto em um toque. Aviso "cole sua chave" quando não há chave.

reaproveita ShizukuShell

Guardião do Shizuku já existe

isReady() / needsPermission() / requestPermission() já estão prontos. A tela do Claude é onde a saúde do Shizuku aparece e se conserta.

As três garantias de segurança

  • Chave cifrada, nunca no repo. Keystore + DataStore. O campo nas Configurações fica pronto pra você colar depois.
  • Gate de confirmação obrigatório pra todo comando destrutivo. Sem exceção.
  • Shizuku caído não falha em silêncio — banner claro. E o app rootless não consegue reiniciar o Shizuku sozinho após reboot; a honestidade é detectar + consertar em um toque.
